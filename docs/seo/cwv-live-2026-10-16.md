## 4. Failures and top fix candidates

Failing gates: **Lighthouse mobile performance (all 3 pages), LCP (all 3 pages), initial payload (home, /latest)**. Evidence below comes from Lighthouse 12 audits (the same engine PSI runs; PSI itself was unavailable).

1. **LCP/payload — oversized CMS hero JPEG.** `https://cms.shikkha24.com/api/media/file/2.jpg` transferred **1 638 123 B (1.56 MB)** in the traces and is both the LCP element on the homepage and ~85 % of home payload. Audit waste on this file: responsive-images 1 326 746 B, modern-format 1 310 453 B, optimized-images 1 005 529 B (mobile home). Fix: emit responsive AVIF/WebP variants + correct `srcset`/`sizes` (the site already ships its card images as 4–33 KB AVIF under `/_astro/`), add explicit `width`/`height` and `fetchpriority="high"` on the LCP `<img>`. ⚠ Anomaly observed: ~2 min after the traces, the same URL returned **HTTP 404 then HTTP 500 (JSON error body)** while the live HTML still references it — verify CMS media-URL stability; a broken hero changes the LCP element entirely.
2. **Render-blocking CSS/script chain.** `/_astro/Layout.8URdw-d6.css` wasted 150 ms (mobile home + latest; 300 ms contact) and on the desktop-home trace `/_astro/index.CwnHxQOg.css`, `/_astro/AdSlot.Q5kZCmPn.css` and `theme-init.js` wasted up to 2 473 ms each. Fix: inline the critical CSS in the HTML head, load secondary CSS asynchronously (`media="print" onload` / preload-swap), inline the 1.6 KB `theme-init.js`, and take `AdSlot.Q5kZCmPn.css` out of the render path (lazy-load with the ad slot).
3. **Edge-cache misses hitting a slow origin.** HTML is `max-age=0, must-revalidate`, and the measured `/contact` HTML was served with `cf-cache-status: MISS`; lab `server-response-time` (origin path) measured 43.4 ms (home, HIT) vs **1 151.7 ms (/latest)** and **4 946.7 ms (/contact)** — that origin latency drives /contact's FCP 6 174 ms → Speed Index 24 068 ms and its perf score 56. Fix: serve HTML with `s-maxage` (even 60–600 s) or a CF Cache Rule / stale-while-revalidate so edge misses don't serialize on origin.

Additional (not in top 3): fonts `solaimanlipi-400.woff2` (70 275 B) + `solaimanlipi-700.woff2` (88 236 B) ≈ 154 KB on every page — preload, subset (Bengali unicode-range) and confirm `font-display: swap` to shave FCP.
