## Design decisions taken in this section

### Subcategories: a self-relation on `Categories`, not a second collection

`docs/content-model.md` and `.sps/task.md` list `Subcategories` as a separate
collection, but the **approved** category tree
(`docs/education-feature-inventory.md` §1) is **flat — 8 top-level categories with
no subcategories defined**, because স্কুল-কলেজ was deliberately rejected as a
category and replaced by the level filter.

Those two positions conflict, so: the **mechanism** exists (an optional
self-relation `parent` on `Categories`), and the **seed is the approved flat
tree**. Editors can add subcategories later — "dynamic and admin-editable" is an
approved decision. A parallel `Subcategories` collection would duplicate the
hierarchy, split internal linking, and give two ways to express the same thing.

⚠️ Raised for the owner: `.sps/task.md` still lists `Subcategories`. Recommend
amending it rather than building an unused second collection.

### `readers` — an addition to the content model

Not in the original inventory. The retained feature set includes comments with
Facebook/Google login, bookmarks, saved deadlines and push notifications — all
four need a persistent reader identity, and `SavedDeadlines.reader` is modelled as
a relation, which needs a collection to relate to.

Kept in a **separate auth collection from `users`** so a reader account is never
one field-level mistake away from editorial access.

### Access control is enforced at the API layer, not the UI

`docs/security.md` §3: "Hiding a button is not authorisation." Every restriction
is a server-side `access` function or a field-level `access` on the field itself.
The most important one: **`users.roles` is field-restricted to Super Admin** —
without it any authenticated reporter could grant themselves Editor-in-Chief with
a crafted `PATCH /api/users/<id>`.

## Findings from this section

1. **Payload's generated types must be regenerated after adding collections.**
   Without `payload generate:types`, every `relationTo` fails with
   `Type '"articles"' is not assignable to CollectionSlug[]` — 20 errors that all
   trace back to one stale file.
2. **`Access` functions take `AccessArgs`, not a user.** `isEditorial(req.user)`
   type-errors; added `isEditorialUser(user)` as the predicate form. An easy
   mistake, now guarded by a comment.
3. **The Bengali locale key must be `bn-BD`, not `bn`.** date-fns has no plain
   `bn`, and Payload validates the key against its supported-language union.
4. **Payload's per-slug method overloads cannot type a union slug.** The seed's
   generic helper needed one confined, documented cast.
5. **Do not run `payload run` while a dev server holds the same SQLite file.**
   Both processes push the schema; the second can fail with
   `index ... already exists`. Confirmed as a collision, not a seed bug — against
   an isolated database the seed is fully idempotent (`created 0, unchanged 77`).
