# S15 — Live TV

**Status:** ✅ **BUILT 2026-09-28** · **Requested as:** feature #5
**Specification:** `docs/feature-batch-2.md` §4 · **Index:** `docs/feature-register.md`

## Owner decisions that constrain this section

| Decision | Answer | Date |
|---|---|---|
| Video source | **Both YouTube and Facebook** — the CMS stores the provider, the page picks the player | 2026-09-18 |

⚠️ **Self-hosted streaming is impossible.** It needs a VPS with RTMP/nginx, which violates
the zero-recurring-cost constraint. An embedded player is the only feasible path.

## What was built

### 1. `LiveStreams` collection — `cms/src/collections/LiveStreams.ts`

`title` · `provider` (youtube / facebook) · `videoId` · `pageUrl` · `isLive` · `scheduledStart` ·
`scheduledEnd` · `description` · `poster`. Wrapped in `withRebuildTrigger`: editing a stream must
reach the static site, so it schedules a rebuild like any other published content.

**Two things the field list alone does not convey:**

- ⚠️ **The value becomes an iframe `src`, so the host is checked at the CMS**
  (`cms/src/lib/live-stream.ts`). `socialUrlValidator` deliberately does *not* restrict a field to
  the platform's domain — its output is an `href` and the runtime guard is a scheme check. Framing
  an arbitrary origin is a much stronger capability than linking to one, so
  `facebookVideoUrlValidator` accepts only Meta's own hosts (`facebook.com`, `fb.watch` and their
  variants) over `https`. Both validators are guard-rails; the control is the frontend, which
  re-validates and assembles the frame URL from a fixed template.
- ⚠️ **The provider-conditional requirement is enforced.** `videoId` is required when the provider
  is YouTube and `pageUrl` when it is Facebook, via a `validate` that reads `siblingData`. An empty
  `videoId` on a YouTube row renders a player with no source — which looks like a broken page
  rather than a missing field.

### 2. `MediaEmbed.astro` — one click-to-load player for both providers

The owner chose **both** providers, and the two differ only in the frame URL. Keeping them in one
component means the click-to-load behaviour, the reserved 16:9 box and the runtime re-validation
exist **once**, so a later change cannot land on one provider and miss the other. `S17`'s `/video`
hub reuses it.

**Zero third-party requests on load** — verified on the built page:

| Assertion on `dist/live-tv/index.html` | Result |
|---|---|
| `<iframe>` | **0** |
| `youtube-nocookie` in the markup | **0** (it exists only in the hashed bundle) |
| Third-party URLs in the markup | **1** — the fallback `<a href="https://www.youtube.com/watch?v=…">`, which is a *link*, not a request |

The trigger is a real `<a>`, so with JavaScript unavailable the reader still reaches the stream;
the script only takes over the click. The poster is self-hosted for the same reason the S9 video
block's is: YouTube's own thumbnail would be a third-party request on every page view.

### 3. `/live-tv` — `frontend/src/pages/live-tv.astro`

Plays the live stream when one is flagged, falls back to the most recent recording between
broadcasts, and lists what is scheduled under **আসছে**. With nothing configured it renders an
honest empty state — **no player and no ad slot**, because an ad on a page with no content is worse
than no ad. The route still exists and stays in the sitemap, so a reader following a link from a
broadcast day does not land on a 404.

Added to the footer's section list and to `sitemap.xml` (priority 0.6, `changefreq: daily`).

### 4. 🚨 The third CSP profile — the architectural change this section forces

`/live-tv` frames YouTube **and** Facebook. Neither existing profile can express that:

| Profile | `frame-src` | Why it fails |
|---|---|---|
| Strict | `'none'` | The iframe is blocked |
| `SHIKKHA24_CSP_RELAXED` | ad domains only | **No video** — silently blocked |
| `SHIKKHA24_CSP_ARTICLE` | YouTube + ads | **No Facebook**; semantic drift to use an `_ARTICLE` variable for a non-article route |

Widening `RELAXED` was **rejected as a security regression** — the homepage, every category listing
and `/quiz` would gain iframe permission they do not need.

**Built: `SHIKKHA24_CSP_MEDIA`, scoped to `/live-tv` alone** — one
`SetEnvIf Request_URI "^/live-tv/?(\?.*)?$"` tag and one `Header … env=` consumer, identical to the
article profile except for the Facebook entries in `frame-src`.

⚠️ **Three things fail silently on their own**, so all three are asserted:

1. **Tagged but no consumer** → the page falls to **strict** and the player is blocked with no
   error anywhere. Same class as the `/article/*` rule that stopped matching at S11.
2. **The tag leaks sitewide** → iframe permission spreads to routes that do not need it.
3. **`frame-src` omits one provider** → that embed is blocked while the other works, so the page
   looks half-broken.

⚠️ **`verify-apache.mjs` was taught the third profile, keyed on `data-media-embed`** — the
attribute `MediaEmbed.astro` emits. Keying it on the `/live-tv` path would be a second copy of the
`.htaccess` regex, which is exactly the M14/M16 mistake. The route loop was also restructured: the
old `hasAd`-first branching mis-classified a media page with no ad slot as merely "over-relaxed".
The new logic keys on the **direction that matters** — a page that needs a relaxation and does not
get one is a failure; a page with a wider policy than it needs is a note.

### 5. Demo fixture — `seed:demo` gains one live stream

⚠️ **This row is not decoration, it is what makes the gate non-vacuous.** `verify:apache` decides
the expected profile from `data-media-embed`; with no stream configured the page self-hides, no
player renders, and the media branch is never exercised. Removed by `seed:demo:purge` on the same
`ডেমো:` title prefix the education rows use.

⚠️ **It had to be reconciled on the *early-return* path too.** `seedDemoEngagement` bails out once
the gallery exists, and that gallery predates S15 — so on any existing database the early return is
the only path taken, and the first version of this fixture silently created nothing. Caught by the
seed report printing `liveTv 0`.

**Counter-proofs (a gate that cannot fail is decoration):**

- **The tag is load-bearing.** `SHIKKHA24_CSP_MEDIA=1` was stripped from both `.htaccess` copies and
  both gates re-run: `verify:apache` reported
  **`/live-tv is served the media profile — HTTP 200, got strict`** and `verify:build-output`
  reported **`0 rule(s) matching /live-tv`**. Restored and re-verified in sync.
- **The relaxation did not leak.** `verify:build-output` asserts the relaxed profile's `frame-src`
  contains no video host, so the rejected option cannot be quietly reintroduced. The harness's
  `mustBeStrict` list (`/about`, `/search`, …) would catch a sitewide leak from the other side.
- **The media branch is non-vacuous.** The demo live stream makes `data-media-embed` present in the
  build, which is asserted as a reported note rather than a hard check — `/live-tv` self-hides when
  the collection is empty, and a legitimate empty state must not turn a gate red.

## Deviations & open items

- ⚠️ **`liveTvTop` was added to `AD_POSITIONS`** (both `cms/src/collections/AdUnits.ts` and
  `frontend/src/lib/ads.ts`) because spec §4.3 says the route carries an ad slot, and the
  `AD_POSITIONS` contract requires a position and a slot to land together. The slot renders **only
  alongside a player** — see above.
- ⚠️ **Facebook embed hosts are enumerated in three places** — `cms/src/lib/live-stream.ts`,
  `MediaEmbed.astro` (build time) and its bundled script (runtime). The build-time and runtime
  copies are deliberate (the runtime one is the control; the build one decides what reaches the
  markup), but the CMS copy is a guard-rail that could drift. Grepping for `fb.watch` finds all
  three.
- The `verify:search-init` SKIP and the S13 `/admin/reporter` manual check remain outstanding and
  are unchanged by this section.
