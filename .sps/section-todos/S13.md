## What was built

### 1. Verification model — `Authors` gained a `verification` block

Flat fields (not a nested `group`) so access rules, `where` queries and the frontend can
address `verificationStatus` directly:

| Field | Notes |
|---|---|
| `reporterId` | `SHK-R-YYYY-NNNN`, unique, hook-generated, not editable after creation |
| `verificationStatus` | `unverified` · `pending` · `verified` · `suspended` |
| `verifiedAt` / `verifiedBy` | Audit — derived from the request, never from the body |
| `validUntil` | Press-card expiry; the public profile shows an **expired** state |
| `verificationNote` | Internal only — `read: authenticated` |
| `joiningDate`, `beat`, `district` | Coverage; `editorialField` so a reporter may keep their own current |

### 2. `Assignments` collection (new)

Editor → reporter work queue: `title`, `brief`, `assignedTo`, `assignedBy`, `dueAt`,
`priority`, `status`, `filedArticle`, `district`, `editorNote`.

**Read access is the security-critical part:** a reporter gets a `Where` clause limiting them
to rows assigned to **their own author profile**; Section Editor and above see the whole board.
A reporter with no linked profile sees **nothing**, not everything — `relationId()` returning
null falls through to `false`.

Deliberately **not** wrapped in `withRebuildTrigger`: an assignment never appears on the public
site, so scheduling a rebuild for it would spend CI minutes for no reader-visible change.

### 3. Three hooks

| Hook | Purpose |
|---|---|
| `assignReporterId` | `SHK-R-YYYY-NNNN`, anchored to the **Dhaka** year, sequence looked up via `sort: '-reporterId'` (the zero-padded sequence sorts lexicographically in numeric order) |
| `stampVerification` | Stamps `verifiedAt`/`verifiedBy` only on the transition **into** `verified`; re-saving an unrelated field does not move the date |
| `guardAssignmentStatus` | A reporter may reach `accepted`/`inProgress`/`filed`; `approved`/`rejected` are editors only |
| `guardPublishStatus` | **See the defect below** |

### 4. Verification harness — `pnpm --filter @shikkha24/cms verify:reporter`

22 checks, all passing. Runs with `overrideAccess: false` so the real `Access`/`FieldAccess`
functions execute against a real `req.user` — a harness that omits it would pass identically
against a schema with no rules at all.

## 🚨 Defects found and fixed

### D1 — A reporter could publish their own article (launch-blocking)

`Articles` documented its rule as *"Publishing itself is `_status: published`, and the
collection `update` access below keeps that to editors."* **That was false.**

- `update: isEditorial` — which **includes `reporter`**, because a reporter must be able to
  save their own draft.
- `_status` carried **no field-level restriction**.

So `PATCH /api/articles/<own-id>` with `{"_status":"published"}` put an unreviewed story on the
live site. **The harness asserted the opposite and failed**, which is how it was found.

Fixed by `guardPublishStatus` (`cms/src/hooks/publish.ts`). It **throws** rather than silently
stripping the field, unlike `reviewStatus`: a stripped write returns 200 and leaves the reporter
believing the story went live, which is the wrong answer for the most consequential action on
the site. It compares against `originalDoc` so it fires only on the transition, not on every
later save of an already-published article.

The misleading comment is corrected in place.

### D2 — `isSelfOrAdmin` cannot be used on `authors`

`Authors.update` was `isSelfOrAdmin`, which compares the **document** id to the **user** id.
Correct for `users`; wrong here, because the link is `Users.authorProfile → authors`, so the two
ids are different numbers and the `where` clause matched nothing. The effect was a flat **403 on
a reporter editing their own profile** — while the comment above it claimed reporters could.

Replaced with `isOwnAuthorProfileOrEditor`, which resolves the relationship and denies when
there is no profile linked.

## Environment note — the Drizzle stale-index trap, again

Adding a collection forced Drizzle to rebuild `authors` and `payload_locked_documents_rels`,
and every push then failed with `index … already exists` (SQLite index names are
database-global, so the rebuild's `CREATE INDEX` collides with the existing one). Resolved by
dropping the named indexes and retrying — twice, iteratively. **Backed the DB up first**
(`data/payload.db.bak-20260918-173622`).

### D3 — The timezone fix had shipped two broken imports (and nothing could see it)

While wiring the byline badge, the full build failed with
`ReferenceError: formatBnBd is not defined` — from **`CommentSection.astro`**, whose import edit
had silently failed during the 2026-09-16 timezone fix (the same-file parallel-write trap). A
sweep found a second one: **`DeadlineStrip.astro`**.

Neither was catchable before now:

- **`tsc --noEmit` never sees `.astro` frontmatter.** `@astrojs/check` is the tool that would, and
  it rejects TypeScript 7 — which is *why* Biome was adopted. So an undefined identifier in a
  component is neither a type error nor a lint error.
- **The thin build passed** because `CommentSection` self-hides without a CMS origin and
  `DeadlineStrip` renders nothing without deadlines. Both only execute on a **full** build
  against a live CMS — the "a green build is not a full build" lesson again, this time hiding a
  crash rather than a missing page.

**Closed with a new gate: `pnpm verify:astro-imports`** (`scripts/verify-astro-imports.mjs`).
Every name exported as a runtime value from `src/lib/*.ts` that is *used* in an `.astro`
frontmatter must also be *imported* there. Counter-proved by removing the `formatBnBd` import
from `CommentSection.astro` — it fails, naming the file and identifier — then restoring it.
Wired into `pnpm verify` and `ci.yml` (before the build: it needs no build, and failing there is
faster and clearer than failing inside the prerender).

### D4 — `reporterId` was never backfilled onto existing authors

The hook was written as `operation === 'create'` only. Correct-looking, and wrong: **every author
that already existed when S13 shipped would have been left permanently without an ID**, so their
badge would render while the ID line beside it stayed empty — and no save would ever fix it. A
credential some holders can never obtain is not a credential.

The hook now assigns on any save where the field is absent. Self-healing on save **is** the
migration. Verified: three demo authors created before the hook went from blank to
`SHK-R-2026-0001…0003` on the next seed run.

### D5 — the harness polluted the database it tested

Three crashed runs left fixtures behind (6 authors, 9 users, 1 article, 4 assignments), and
because they carried real slugs they generated **real pages** — `/reporters/verify-a-…` appeared
in `dist/`.

Two fixes: cleanup now runs in a **`finally`**, so a throwing run still cleans up; and the harness
**purges stale `verify-` fixtures at startup**, which is safe because that prefix is a reserved
namespace no real content may use. Verified: the purge removed all 20 orphans, and a post-run
query shows zero residual rows.

## Demo corpus now exercises the routes

`/reporters/[slug]` generated **nothing** on the first build — no demo author was verified, so the
route had never run. Per M17 (a boundary-sized fixture hides defects *and* hardens wrong
assumptions), the demo corpus now covers all three verification states:

| Author | State | What it exercises |
|---|---|---|
| `demo-reporter` | verified, card in date | badge, listing, profile, byline mark |
| `demo-desk` | verified, card **expired** | the "মেয়াদোত্তীর্ণ" branch |
| `demo-correspondent` | unverified | proves `/reporters` **filters**, not merely labels |

The seed was also made **convergent** for these fields (it previously skipped an existing author
entirely), so re-running it reaches the same end state rather than merely avoiding duplicates.

**Verified against the built output:** 147 pages; `/reporters/demo-desk` and
`/reporters/demo-reporter` generated; `/reporters` links both and **excludes**
`demo-correspondent`; the profile shows `SHK-R-2026-0001`; `demo-desk` renders the expired state;
and **17 article pages carry the verified byline badge**.
