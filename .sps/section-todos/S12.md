### 11. ⚠️ CSP route coverage — regression found and fixed

**Found during S12:** the S11 URL change moved articles from `/article/:slug` to
`/:category/:id/:slug`, but the relaxed-CSP rule in `frontend/public/.htaccess`
(formerly `_headers`) still read `/article/*`. It therefore matched **no article
page at all** — every article would have fallen to the strict profile in
production, blocking AdSense and the video-embed `frame-src`, with no error
anywhere.

This is the same failure class as the S8 CSP bug: a policy applied by Apache
that nothing local reveals.

**Why a wildcard cannot fix it.** The `.htaccess` `<LocationMatch>` uses
regex (replacing the former Cloudflare Pages `_headers` splat/placeholder
semantics):

- a splat (`*`) matches greedily and **crosses `/`**, and only **one splat** is
  allowed per rule — so `/*/*/*` is invalid;
- a placeholder (`:name`) matches all characters **except `/`** — exactly one
  path segment.

An article URL shares no literal prefix with its category listing
(`/admission/10/slug` vs `/category/admission`), so no prefix rule can express
it. The fix is the placeholder pattern:

```
/:category/:id/:slug
```

**Verified** by `scripts/verify-csp-routes.mjs`, wired into `pnpm verify`:

| Check | Result |
|---|---|
| Article rule uses the placeholder pattern | ✅ |
| Stale `/article/*` gone from the relaxed set | ✅ |
| No rule uses more than one splat | ✅ |
| Every built article path (12) gets the relaxed CSP | ✅ |
| Strict profile kept for `/latest`, `/search`, `/bookmarks`, `/gallery`, `/gpa`, `/page/*`, `/institutions/*`, `/study-abroad/*`, `/author/*` | ✅ |
| Placeholder does not over-match (`/admission`, `/category/admission`, `/category/admission/page/2` all rejected) | ✅ |

**Counter-proof:** running the matcher against the old pattern —
`/article/*` vs `/admission/10/demo-admission-circular-dhaka` → **false**;
`/:category/:id/:slug` → **true**. The harness fails on the old rule, so it
genuinely catches the regression rather than passing vacuously.

**Docs kept in sync:** `docs/security.md` §5 now lists the relaxed route
patterns and records that the media host is the CMS origin (not the retired R2
domain); the CMS comments in `blocks/editors.ts`, `blocks/VideoEmbedBlock.ts`
and `collections/Articles.ts` no longer point at the dead `/article/*` prefix.
