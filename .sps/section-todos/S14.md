## Owner decisions that constrain this section

| Decision | Answer | Date |
|---|---|---|
| Facebook posting | **Share button only** — no Graph API, no page token, no app review | 2026-09-18 |
| Where generation runs | **Server-side at the CMS**, on demand — not in the browser, not at build time | spec §3.2 |

**Why server-side:** a browser cannot be trusted to render an unforgeable card,
and build-time generation would spend CI minutes on every reporter edit.

## Planned deliverables

| Piece | Notes |
|---|---|
| Dependency | `qrcode` (MIT) + the already-installed `sharp` 0.35.4 — record justification + license in `.sps/handoff.md` (rule 8) |
| `GET /api/idcard/:reporterId.png` | Portrait card (1000×1600): photo, name, designation, `reporterId`, press card no, validity, beat — plus a QR → `/verify/<reporterId>` |
| `GET /api/photocard/:articleId.png` | Square social card (1200×1200): featured image, category chip, headline, date, wordmark, QR → canonical URL |
| Caching | `Cache-Control: public, max-age=86400`, versioned by the record's `updatedAt` (`?v=<epoch ms>`) |
| `/verify/[reporterId]` | **Static**, 2 segments (no article-rule collision). Unknown or suspended → an explicit **"যাচাই করা যায়নি"** state, never a blank page |

⚠️ **Headline wrapping must use `formatBnBd()`** — the timezone contract applies to
generated images too.

## Exit gates

- [ ] The same card generated twice is **byte-identical**
- [ ] The QR resolves to a live `/verify/:id` page
- [ ] An unknown ID renders "যাচাই করা যায়নি", not a 404 or a blank page
- [ ] Build + typecheck + lint + all `verify:*` gates pass
