## What was built

### 1. `qrcode` dependency (rule 8)

| Package | Version | License | Justification |
|---|---|---|---|
| `qrcode` | `1.5.4` (exact pin) | **MIT** | Server-side QR → PNG buffer, Node only, never the browser. `sharp` 0.35.4 was already installed and does the compositing. No canvas native build, no paid service. |
| `@types/qrcode` | `1.5.6` | MIT | Dev-only types. |

### 2. `cms/src/lib/id-card.ts` — composition (`sharp`)

- `composeIdCard()` — portrait 1000×1600: brand header · circular photo · name · designation ·
  reporter ID · press card no · **blood group** · validity · beat · QR → `/verify/<reporterId>`.
- `composePhotocard()` — square 1200×1200: cover-cropped featured image (darkened) · category
  chip · wrapped Bengali headline · date · wordmark · QR → the article's canonical URL.
- `verifyUrlFor()` — **the single place** the QR target is built, so the card and the page
  cannot drift.

**Bengali shaping was measured, not assumed.** libvips renders text through pango+harfbuzz;
two dead ends were ruled out first — an SVG `<text>` with an embedded `@font-face` data URI
was **ignored by librsvg** and produced ink identical to a no-Bengali-font render, while
libvips's `text` input with an explicit `fontfile` loads the vendored WOFF2 directly and
bypasses fontconfig. Proven numerically: a conjunct cluster (`ক্ষতি`) renders ~40% narrower
than the same characters forced apart — which is what correct যুক্তাক্ষর shaping produces.

### 3. Two public-read endpoints — `cms/src/endpoints/id-card.ts`

| Route | Notes |
|---|---|
| `GET /api/idcard/:reporterId.png` | Malformed ID → 404 with a Bengali message, never a blank image |
| `GET /api/photocard/:articleId.png` | Only `_status: published` articles; drafts have no canonical URL |

Both set `Cache-Control: public, max-age=86400` + an `ETag` of the record's `updatedAt`.
Public read is deliberate: a card exists to be scanned by anyone, and it draws only what
`/reporters/:slug` already publishes. Email, verification note and verifier are never drawn.
The font is read from the standalone bundle root — CI now copies it beside the app, exactly
like `.next/static`, which Next does not copy either.

### 4. `/verify/[reporterId]` — the QR landing page

Photo, name, designation, reporter ID, press card no, validity (**with an expired state**),
beat, verification badge, and an explicit **"যাচাই করা যায়নি"** state for an unknown ID.

### 5. Card surfaces on the site

- `/reporters/[slug]` — a verified reporter gets the card preview, a **PNG download**, and a
  **Facebook share** link (`sharer.php`), plus a pointer to the QR landing page. Shown only
  for a verified reporter: drawing a credential the site itself calls inactive would be a lie.
- Article `ShareRow` — a **কার্ড** link to the photocard. A plain link, not an `<img>`: the
  card is fetched only when tapped, so the article page pays nothing.

## 🚨 Defects found and fixed

### D1 — The "যাচাই করা যায়নি" state was **unreachable in the built site** (exit gate failed)

The exit gate reads *"An unknown ID renders 'যাচাই করা যায়নি', not a 404 or a blank page."*
The page implemented that branch, and its header comment claimed it worked — *"an ID not in
the CMS at all still renders the not-found state, because the page is static and the route
exists regardless."* **That claim was false.**

`getStaticPaths` returned only the IDs that exist, and a static build emits **only** those
paths. `/verify/<unknown>` reached Apache's generic 404. The branch was dead code that read
as covered, and it was verified by nothing: `verify:id-card` checked that a *known* ID's page
exists, which is the opposite direction.

**Fixed** by making the state reachable on a static host:

1. `getStaticPaths` now also emits a **`not-found` sentinel** — a reporter can never collide
   with it, because `reporterId` is hook-generated as `SHK-R-YYYY-NNNN`.
2. `.htaccess` gains the file's **first `mod_rewrite` block**: any `/verify/<something>` that
   is not a real file or directory is served that sentinel. The reader's URL is unchanged.
3. The page carries `noindex` (new `Layout` prop) — it answers **200** by design, so without
   it the soft-404 would be indexable.

⚠️ The two `RewriteCond`s are load-bearing: a real `/verify/SHK-R-…/` is a **directory**, so
`-d` skips the rule. Drop either condition and **every card collapses into the not-found
state while still returning 200** — which a status assertion alone would not catch. That is
why `verify:apache` now counter-proves it with a real reporter ID.

### D2 — `bloodGroup` was silently dropped from the card (plan drift, rule 13)

Spec §3.3 lists the card as *"… pressCardNo · **blood group** · validUntil · beat …"*. The
`Authors` collection had no such field and the card drew no such row. `bloodGroup` appeared
**once in the entire repository** — in the spec — so nothing flagged it.

Added as an optional `select` (A+ … O−) with Bengali labels, drawn as one more credential row.
An optional field simply does not draw when empty, so a reporter without one still gets a
valid card. This is a real-world requirement rather than a nicety: blood group is a standard
element of a Bangladeshi press card, and it is read in emergencies.

⚠️ **Adding a Payload field requires `pnpm --filter @shikkha24/cms generate:types`** —
`payload-types.ts` is generated, so `tsc` fails on the new property until it is re-run. The
failure reads as a code error, not a stale artifact.

**Counter-proofs (a gate that cannot fail is decoration):**

- **The rewrite is load-bearing.** The `mod_rewrite` block was stripped from both `.htaccess`
  copies and the harness re-run: `FAIL — an unknown reporter ID renders the not-found state,
  not a 404 — HTTP 404`. Restored and re-verified in sync.
- **The rewrite is not over-broad.** A known ID is asserted **not** to be rewritten.
- **The card is not a blank plate.** Ink is counted: 415,779 non-white pixels on the ID card.
- **The QR is deterministic.** The URL is built in one place and asserted against a regex.
