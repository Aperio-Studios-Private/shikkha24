## The blocking defect this section existed to fix

S1 shipped an `AdUnits` collection with a **placeholder** position vocabulary —
`headerBanner`, `inArticleTop`, `sidebarSticky`, `footerBanner` — written before the layout
existed. The frontend, meanwhile, addressed its slots with free-form labels:
`homepage-leaderboard`, `sidebar-rectangle-1`, `article-footer`.

**The two sets did not intersect.** No ad unit could target any slot on the site, so the
collection was inert: an editor could configure an ad and it would never appear anywhere.

Reconciled to the eight slots that actually exist, each with exactly one `AdSlot`:

`homepageLeaderboard` · `homepageFooter` · `sidebarTop` · `sidebarSticky` ·
`categoryLeaderboard` · `articleTop` · `articleMiddle` · `articleBottom`

The collection held no data, so the change was free. The names are now a **contract**: a
position with no slot renders nothing, and a slot with no position renders the placeholder.

## Two decisions worth recording

### 1. No raw-HTML field (security)

The original collection carried a `codeSnippet` textarea for pasting AdSense code. **Removed.**
Rendering CMS-authored HTML into a public page is a script-injection vector — a compromised
Ad Manager account would become stored XSS on every page carrying the unit, and
`docs/security.md` §4 requires input to be structured and escaped, never executed.

Instead the markup is generated from structured fields (`adsenseSlotId`, `image`,
`targetUrl`), so there is no path from the admin to arbitrary markup.

### 2. `clickCount` removed (honesty)

The original had a read-only "Clicks" field. **A static site cannot increment it** — there is
no server in the request path, and posting beacons to the CMS from the reader's browser would
give up the property that a CMS outage cannot take the site down (`docs/reliability.md` §1).
A field that always reads 0 is worse than no field. Click measurement is deferred to
Apache access log analysis (cPanel).

## Zero CLS

`docs/performance-budget.md` §1 requires every ad container to be reserved, and ads to load
**after LCP**, never above the fold in the initial payload.

- Every `AdSlot` sets `width`/`max-width`/`height` on its wrapper **before** any ad loads, so
  the box exists whether or not an ad fills it.
- The AdSense library is **not** the copy-paste `<script>` in `<head>`. `AdCreative` injects it
  on `window.load` → `requestIdleCallback`, so it never competes with the LCP image.
- In-article ads are placed **after** the header block, so they cannot land in the initial
  viewport.

**With no ad unit configured, zero third-party requests are made** — the loader finds no
`ins.adsbygoogle` and returns. That is what keeps the no-ads Lighthouse profile at ≥95.

## Mid-article placement

`inArticleMiddle` required splitting the rendered body. `lib/richtext.ts` gained
`countParagraphs` and `splitHtmlAtParagraph`, which cut **only immediately after a `</p>`**,
so no tag is ever sliced and the halves rejoin to the original string.

The ad only appears at **6+ paragraphs**, split at the midpoint. On a four-paragraph story an
"in-article" unit lands beside the byline and reads as a mistake, so it is skipped.

## CSP — a finding that would have broken AdSense silently

`frontend/public/_headers` documented a planned two-profile CSP, with the relaxed profile
"applied per-route at S7". Researching the mechanism before implementing it turned up a trap:

> **Cloudflare Pages does not override a duplicated header — it joins the values with a
> comma.** A comma-joined CSP is enforced as *two* policies, so the strict
> `script-src 'self'` would still have blocked AdSense. A more specific rule must **detach**
> the inherited value (`! Content-Security-Policy`) before setting its own.

The relaxed profile is now attached to `/`, `/article/*` and `/category/*` — exactly the three
routes carrying slots — each detaching the strict policy first. Every other route keeps the
strict profile.

⚠️ **Note (2026-09-14):** Cloudflare has been removed entirely. The `_headers` file is
replaced by `frontend/public/.htaccess` (Apache). Apache's `Header set` replaces the value
cleanly — **no comma-join problem**. The `!`-detach trick is Cloudflare-specific and is not
needed with Apache. The two-profile CSP design is preserved via `<LocationMatch>` blocks.

⚠️ **S12 check:** confirm in production that an ad-bearing page returns exactly **one**
`Content-Security-Policy` header. If it contains a comma, the detach did not take effect and
the CSP must move into a Pages Function.

## Sponsored content

`isSponsored` + `sponsorName` on Articles, rendered by one component in two shapes:

- **banner** above the headline — a reader cannot start the piece without knowing it is paid for
- **badge** in the byline and on listing cards

Sponsored stories are **excluded from the masthead and the breaking ticker** but stay in
category sections and the latest feed, where they carry the label. A paid placement in the
lead slot would borrow the authority of the front page; the label makes it honest but does not
make it the day's most important story.

**A bug this surfaced:** `remainingLatest` was `latest.slice(1)`. Once a sponsored story was
dropped from the masthead, the promoted story became the lead *and* re-appeared as the first
item of the latest feed — the same headline twice on one page. Now the feed excludes whatever
the masthead showed, matched by slug rather than index.

## Notes for review

- **The demo articles are not sponsored**, so the sponsored template shows nothing on the
  built site. To preview it: set **স্পনসর করা কনটেন্ট** on any article in the admin, add a
  sponsor name, and publish.
- **AdSense is not serving yet.** The loader is wired and the CSP is in place, but no AdSense
  unit exists and `SiteSettings → Tracking → AdSense client id` is empty. To go live: set the
  client id, then create an Ad unit per slot with its AdSense slot id. The
  `PUBLIC_FLAG_ADS=false` switch removes every slot from the next build.
- **AdSense account activation ≠ serving.** Google requires a live site with content before
  ads deliver, so expect a review period after launch (`docs/performance-budget.md` §1).
