## Fixed 2026-09-15: `/latest` pagination was broken, and nothing could see it

`pages/latest.astro` was a single page that read `?page=N` from the URL. On a
static build `Astro.url.searchParams` is evaluated **at build time**, where there
is no query string — so `page` was always 1 and every page rendered the same
twelve articles. Meanwhile `Pagination` builds its links as `${basePath}/page/${n}`
— path segments, not a query string — and **no route emitted `/latest/page/2`**.
The moment a thirteenth article was published, `/latest` would have rendered a
"পরের →" link pointing at a 404.

It was invisible because the demo corpus held **exactly** twelve articles and
`PAGE_SIZE` is 12, so `totalPages` was always 1 and the control never rendered.
The same corpus boundary also hid a CSP defect: the article rule matched any
three-segment path, and `/latest/page/2` is three segments, so page 2 would have
been served the *article* profile (relaxed, with `frame-src` for video embeds)
despite carrying no ad slot. See M17.

Now `pages/latest/[...path].astro` — the same catch-all shape the category route
uses, so listing behaviour lives in one place — and `scripts/verify-links.mjs`
checks every internal link in the built output, so this class cannot return
quietly.

## Two design notes

**Breadcrumbs generate the visible trail and the JSON-LD from one array.** A
breadcrumb that shows one thing to the reader and tells Google another is worse
than no breadcrumb. Sharing the source makes drift impossible.

**`getStaticPaths` fetches page 1 to learn the page count, then emits one path
per page.** Category pages therefore scale with content — a category with 300
articles emits 25 pages automatically.

## Deferred (with the groundwork done)

**Author profiles, tag pages and date archive** are not built as routes, because
the demo content has no tags and exactly one author — there would be nothing to
look at. The CMS layer is already written and verified:

- `getTagBySlug(slug)` / `getArticlesPage({ tagSlug })`
- `getAuthorBySlug(slug)` / `getArticlesPage({ authorSlug })`
- `getArchiveBuckets()` → year/month buckets with Bengali labels and counts
- `getArticlesByMonth(year, month, page)`

Each route is ~30 lines using the existing `ArticleGrid` + `Pagination`. Say the
word and they are a single commit.

**Subcategory filters** render when a category has children via the
`categories.parent` self-relation. They are correctly empty under the approved
flat tree — the mechanism exists for editors who add children later.
