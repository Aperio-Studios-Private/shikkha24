## Why Pagefind

The site is static HTML on DianaHost `public_html` with no server in the request path,
which rules out anything needing a backend. Pagefind builds the index at build
time and queries it in the browser from small per-page fragments — zero runtime
cost, and it works offline once loaded.

It is also the right cost answer: no Algolia, no Elasticsearch, no monthly bill.
The no-card constraint makes a hosted search service a non-starter.

## Index scope

Before `data-pagefind-body`, Pagefind indexed all 24 pages including category
listings, the 404 and the homepage — so a query could return "this story is
mentioned in the footer of a category page". Scoping to the article body cut it
to 12 pages of actual stories. The related-articles sidebar is explicitly
ignored, since those headlines belong to *other* stories and would make an
article match queries it is not about.

## ⚠️ Known limitation: no Bengali stemming

Pagefind prints this at build time:

> Pagefind doesn't support stemming for the language bn. Search will still work,
> but will not match across root words.

This is real, and not something configuration can fix. Search matches exact word
forms — "শিক্ষা" will not match "শিক্ষার্থী".

Mitigations, in order of effort:
1. **Browse fallback (done)** — category chips on the search page, so filtering
   is a first-class route when search comes up short.
2. Synonym list at index time.
3. Keep the 8-category taxonomy tight so browse-and-filter carries discovery.

## Date and section filters — ✅ BUILT 2026-09-15

The last deferred item. `docs/master-plan.md` §S6 calls for a "date-range filter,
section filter" on search; this is it.

**Index side** — `pages/[category]/[id]/[slug].astro` tags each article:

```html
<span data-pagefind-filter="বিভাগ:উচ্চশিক্ষা" hidden></span>
<span data-pagefind-filter="তারিখ:২০২৬-০৬" hidden></span>
```

**UI side** — `public/search-init.js` opens both groups by default
(`openFilters`) and hides values that no longer match (`showEmptyFilters: false`,
so the two filters cascade).

### Three decisions worth keeping

1. **The filter keys are Bengali.** Pagefind UI renders the *filter key* as the
   group heading and ships **no per-filter label translation** — only
   `filters_label` ("Filters"). An English key would put an English heading on an
   otherwise Bengali page.
2. **The date value is `YYYY-MM` in Bengali numerals** (`২০২৬-০৬`). Bengali digits
   run U+09E6–U+09EF consecutively, so the value still sorts chronologically as a
   string — which a month *name* would not.
3. **The month is derived from the same `toISOString()` basis the byline uses**,
   so the filter and the displayed date can never disagree.

### ⚠️ Pagefind renders filter values in index order, and cannot be told otherwise

Not a preference — checked. The UI bundle's only `.sort()` call is for
sub-results. The month values come out in whatever order articles were indexed
in — `২০২৬-০৬, ২০২৬-০৮, ২০২৬-০৭, ২০২৬-০৯` in practice. **A date filter listing
August before July is a defect a reader notices**, so `search-init.js` reorders
the date block in the DOM after render.

- The comparison is **codepoint, not `localeCompare`** — Bengali digit order is
  guaranteed; collation rules are not.
- It re-runs via `MutationObserver`, because Pagefind re-renders the filters on
  every search. The re-append is **guarded for idempotence**: re-appending an
  already-sorted list still mutates the DOM, which would re-trigger the observer
  forever.
- `MutationObserver` is **guarded and optional** — Opera Mini runs its JavaScript
  without a DOM, and a missing observer degrades to "unsorted", never "broken".
- The **section** filter is deliberately not reordered: its values are peers, so
  any order reads acceptably.

⚠️ **This depends on Pagefind's internal markup** (`.pagefind-ui__filter-block`,
`__filter-name`, `__filter-value`, `__filter-checkbox`), which is not a public
API. `verify:build-output` asserts those hooks still exist, so a Pagefind update
that renames them **fails the build loudly** instead of quietly disabling the
sort. Counter-proved by renaming one in the built bundle.

### Verification

- **`scripts/verify-search-init.mjs`** runs the *shipped* `search-init.js` against
  a DOM (not a reimplementation of its logic) and checks all eight behaviours,
  including the re-render path and the no-feedback-loop guard. It needs
  `linkedom`, which is deliberately **not** a project dependency — without it the
  harness **skips with a clear message** rather than failing.
- **The real index was queried, not assumed.** The `.pf_filter` files are gzip;
  decompressing them shows `বিভাগ` carrying all 8 categories and `তারিখ` all 4
  months. A `.pf_filter` file existing is not evidence of its contents.

## Notes

- Pagefind UI ships English strings only; all UI copy is translated to Bengali
  in `search.astro` (placeholder, one/many/zero results, searching, load more).
- The UI script and chunk load **only** on `/search`, not site-wide.
- Index size is ~708 KB on disk, but it is fetched as small per-query
  fragments, not as one file.
