## The body renderer — the interesting part

Payload serves `richText` as **Lexical JSON, not HTML**. Options were:
import `@payloadcms/richtext-lexical` across workspaces (pulls React + the
Payload server runtime into a static build), or write a converter. Wrote the
converter — `lib/richtext.ts`, ~150 lines, no dependencies.

Two deliberate properties:
- **Everything is escaped.** Reporter-entered text is still user input. There is
  no "allow raw HTML" path, by design.
- **Unknown nodes are not dropped.** They fall back to their children/text, so a
  reporter who pastes something unanticipated sees their words with slightly
  wrong markup rather than finding a paragraph missing from the published story.

## Two bugs that cost real time

**1. Every article 404'd while the CMS returned 200 for the same URL.**
`HTTP_PROXY` is set in this environment. Astro's build-time `fetch()` honours
it, so `localhost:3000` went through the proxy → **502**. The content layer
degraded gracefully, so the build stayed green while every page silently fell
back to empty data — and `getAllArticleSlugs()` returning `[]` meant no article
routes at all. Symptom: 304-byte redirect stubs in `dist/article/*`.
Fixed with `NO_PROXY=localhost,127.0.0.1,::1` in the `dev`/`build` scripts.

**2. Payload faltered under build-time concurrency.** 12 pages × ~6 fetches
produced transient failures. `lib/cms.ts` now caches every response (and every
failure) by path for the whole build — so a 5,000-article build costs one
request per unique path, not one per page.

Both are recorded in `MEMORY.md`; the first will recur in any sandbox with a
proxy set.
