# S16 — Reader Reactions (built and verified)

## What shipped
`Reactions` collection · `POST /api/reactions/toggle` + `GET /api/reactions/counts` (both
**collection-mounted**) · `ReactionBar.astro` island · `verify:reactions` (9/9) · a
privacy-policy disclosure · CI wiring.

## Decisions worth keeping
- ⚠️ **`Reactions.read` is NOT public — that is a privacy control.** A row holds a
  `fingerprint`, so a public read would let anyone enumerate every fingerprint on an
  article. The aggregate is computed server-side by the counts endpoint; only five counts
  plus the caller's own choice leave the CMS.
- ⚠️ **Two compound unique indexes, and both are needed.** `(article, type, reader)` for a
  signed-in reader (the account survives a cookie wipe); `(article, type, fingerprint)` for
  an anonymous one. **SQLite treats `NULL` as distinct in a unique index**, so the reader
  index cannot constrain an anonymous row at all.
- ⚠️ **The insert is deliberately not atomic** — two concurrent toggles can both see "no
  existing row". The unique index refusing the second is the control, so the handler catches
  that refusal and returns fresh counts rather than a 500.
- ⚠️ **Single-choice is an endpoint rule, not a DB rule.** The spec's two indexes do not make
  "one row per article per fingerprint" impossible, so a crafted request could record two
  different types. Recorded rather than silently adding two more indexes (rule 13).

## 🚨 The counter-proof needed a different method — the finding to keep
**Dropping the unique index out-of-band with `sqlite3` proves nothing.**
`payload run` **re-applies the declared schema on boot**, so the index was silently recreated
before the harness executed — and the harness **PASSED with the index "dropped"**. A
counter-proof that proved nothing, and it looked completely convincing.

The honest method: remove the index from the **collection config**; the schema push then drops
it for real, and the harness reports
`FAIL … a second row was created — the unique index is missing`. Restored byte-identical.

**Counter-prove a schema constraint via the config, never via the database.**

## Traps hit
1. ⚠️ **`pagination: false` is required on the counts query.** Payload's `find` returns one page
   by default, so counting `docs.length` without it silently caps the tally at the page size —
   a wrong number that looks like a real one (trap 10A).
2. ⚠️ **Payload *throws* `Forbidden`** when access is denied on `find`, rather than returning an
   empty page. A harness asserting only `docs.length === 0` fails on the throw.
3. ⚠️ **A relationship column needs a numeric id.** The reader session carries the id as a
   **string** (it is signed, not typed); `payload.create` rejects it for a numeric relationship.
   Parse and range-check rather than cast.
4. ⚠️ **The vocabulary lives in three places** — `cms/src/lib/reactions.ts`,
   `cms/src/collections/Reactions.ts` (admin labels), `frontend/src/lib/reactions.ts`. The CMS
   cannot be imported from the frontend (`node:crypto` + Payload). **Grepping for `angry` finds
   all three.**

· build-output (incl. "no baked counts") · links · apache · sync · `verify:reactions` 9/9 ·

## What shipped

`lib/photo-story.ts` · `lib/video.ts` · `MediaEmbed` above the body · `/video` hub ·

## 🚨 The defect — the most valuable thing this section produced
**`Articles.videoProvider` can be `facebook`, but the article profile's `frame-src` named only
YouTube.** An article carrying a Facebook video would have been **silently dead on the
highest-traffic route**: HTTP 200, valid markup, a valid policy, and the iframe blocked with no
error anywhere.

It surfaced only because S17 made an *article* render a `MediaEmbed` for the first time, so
`verify:apache`'s expectation finally mismatched. Nothing else could have found it.

**Fix — two parts, and the second is the one that matters:**
1. The article profile gained the Facebook hosts in `frame-src`.
2. **The harness became provider-aware.** It reads `data-media-provider` off each page — the
   component's own statement of which provider the reader will frame — and asserts the served
   policy allows **that** provider. A blanket "does the policy mention Facebook" would not have
   caught it, because the real question is whether the policy permits the frame the page creates.

## ⚠️ Consequence: the article and media profiles are now byte-identical
Both env vars remain (they dispatch by different route families, so a later change to one cannot
silently widen the other), but **neither harness alone proves the dispatch any more** — the static
half is `verify:build-output`, the runtime half is `verify:apache`.

`profileOf()` now classifies by **capability** (`relaxed-video` / `relaxed-generic` / `strict`),
not by which env var produced the header. `expectedProfile()` returns `relaxed-video` when the page
renders `data-media-embed` **or** is a `NewsArticle` — the second because an article can embed a
video through its *body* block without ever rendering the component.

## Other traps
- ⚠️ **`/video/page/:n` needed its own rule.** It is 3 segments, and the article rule excludes only
  a `page/` in the **middle** position — so page 2 of the hub would have been served strict and its
  player would have died silently.
- ⚠️ **`/video` features the newest video with a player**, not just cards. The spec calls it a
  listing *and* decides it needs the media profile because it embeds; those only agree if it
  actually embeds. A page of plain cards needs no `frame-src` at all.
- ⚠️ **Fixtures must cover both providers.** With only a YouTube fixture the provider-aware check
  can never fire and the Facebook half of `MediaEmbed` never renders — **which is exactly how the
  defect survived.** One video article per provider is now seeded.

## Photo story notes
A layout, not a collection. Frames render **ahead of** the prose, never instead of it. Box
reservation measured at `--frame-ratio: 1600 / 1067` on all four frames; an unmeasurable image is
**skipped, not guessed**. Scroll-linked with pure CSS behind `@supports` +
`prefers-reduced-motion`, so the frames are readable with JavaScript off.

⚠️ The frame resolution lives in `lib/photo-story.ts`, not in the component, because the page needs
the same list **twice** — to render and to build the JSON-LD. Resolving independently in each place
is how structured data ends up describing images the page does not show.

# The GPA calculator was wrong in three ways (owner report)

Not a new section — this corrects **N6 from S10**.

## Researched first (rule 3), three independent sources
```
৪র্থ বিষয় বোনাস = সর্বোচ্চ(০, ৪র্থ বিষয়ের পয়েন্ট − ২.০০)
চূড়ান্ত জিপিএ = (মূল বিষয়ের পয়েন্টের যোগফল + বোনাস) ÷ মূল বিষয়ের সংখ্যা   [সর্বোচ্চ ৫.০০]
```
Only the part **above** 2.00 is added → maximum bonus is **3.00**, not 2.00, and the 4th subject is
**not** in the divisor. An F in a compulsory subject → **0.00**; an F in the 4th → no bonus, no
penalty.

## The three bugs
1. **`min(GP, 2)` instead of `max(0, GP − 2)`.** An A+ 4th subject gave 2.00 instead of 3.00.
   ⚠️ **The error was always downward**, so the calculator systematically under-reported.
2. **An F in a compulsory subject did not fail the result** — one F with five A+ reported **4.17**
   instead of **0.00**. The one that could mislead someone about whether they passed.
3. **The letter grade was looked up on the wrong scale** — a GPA (5.00 scale) compared against the
   **marks** boundaries (80, 70, 60 …), so the only boundary it could satisfy was 0 and **every
   result read এফ**.

## ⚠️ The root cause was structural, not arithmetic
The calculation lived inside a page `<script>`, so **nothing could call it and nothing could check
it**. That is why three wrong answers shipped and why the wrong rule was written into S10's own
evidence file as the design ("Optional subject's points are capped at 2.0…").

Now: `frontend/src/lib/gpa.ts` (pure) + `scripts/verify-gpa.mjs` (60+ checks) in `pnpm verify` and
CI, plus a `verify:build-output` DOM-contract check.

## Traps
- ⚠️ **`--experimental-strip-types` only strips `.ts`.** The harness must therefore be plain
  **`.mjs`** — a type annotation in a `.mjs` is a hard syntax error, and it fails at *import*, so
  the message points at the import line rather than the annotation. `gpa.ts` must also stay
  **erasable**: no enums, no namespaces.
- 🚨 **The DOM-contract check was wrong first, and counter-proving it found that.** It used
  `bundle.includes('class="gpa-marks')`, which also matches `class="gpa-marks-2` — and a CSS class
  selector matches whole names, so that rename genuinely breaks the query while the check stays
  green. Now compares **whole class tokens** from the `class="…"` attributes.
  **A check written to catch a silent failure is exactly the check that needs counter-proving.**

## Rounding: the sources disagree, and that is not hidden
One says the board *truncates*; another's worked example rounds (`42 ÷ 9 = 4.666…` → `4.67`). The
module returns `rawGpa` unrounded and the page **shows it whenever rounding moved the number**.

## Also fixed
The on-page rule text claimed a 2.00 maximum bonus (now rendered from the constants);
`ঐচ্ছিক (৪র্থ/৫ম)` implied a non-existent 5th optional subject; and the marks input capped at 100,
so the **200-mark combined Bangla and English** papers could not be entered. Each row now carries
its own total (১০০/২০০).

## Counter-proofs
All three bugs re-introduced one at a time → harness red each time with the right diagnostic
(`bonus 2`, `4.1666…`, `band F`). Both DOM checks counter-proved too.

Gates: biome 0 · typecheck 0 · `verify:gpa` all pass · astro-imports 130 · build 155 pages ·
build-output · links · apache — all green.

# CGPA calculator added as a second tool (owner request)

## ⚠️ The two are different SYSTEMS, not two views of one
`/gpa` = school-leaving **5.00** scale (A+ 5.00; an F in a compulsory subject **zeroes** the result).
`/cgpa` = university **4.00** scale (A+ 4.00; marks weighted by credit hours; an F is a **0.00 that
is included**, not an annihilator).

⚠️ **The F rule is the trap and it is the opposite of the school one.** Copying the school rule
would tell a student who failed one course that their CGPA is **0.00** when it may be well above
3.00. That is the case where the number matters most.

## ⚠️ Bangladeshi universities do NOT share one grade table
The scale is a **choice the reader makes**, never an assumption. Two verified presets:

| Scale | Pass mark | 75 marks is |
|---|---|---|
| UGC / public + National University (quarter points) | 40% | A (3.75) |
| Private-university `+/-` variant | 60% | C (2.00) |

⚠️ **The private scale came from NSU's OWN published grading policy, and it disagreed with a
third-party calculator** — which put A at 95 marks where the university says **93**. Third-party
calculators are not authorities on someone else's regulations. Always go to the institution.

## What shipped
`frontend/src/lib/cgpa.ts` (pure, scale-aware) · `scripts/verify-cgpa.mjs` (60+ checks, two
published worked examples) · `/cgpa` with course/credits/grade/term rows, CGPA + degree class +
totals + per-term GPA breakdown · both calculators cross-linked, in header + footer nav, in the
sitemap · `verify:build-output` DOM contract now covers both pages from their own bundles.

## Traps
- ⚠️ **The harness caught two of MY OWN wrong expectations first** — a mis-stated denominator

  expectation down is where a misunderstanding surfaces. That is the point.
- ⚠️ **A class selector can be satisfied by the PAGE, not only by the bundle.** The DOM check

turned the harness red with the right diagnostic. `/cgpa`'s DOM check counter-proved too.

Catalogued the tools that already exist (BD + international): name, region, what each calculates,
how it helps students. Headlines:

- **Very few tools cover both BD systems** — most do SSC/HSC *or* university. That is why our two

- 🚨 **Third-party calculators are not authorities on someone else's regulations, and at least one

  features.**

  need" (it can say *impossible* — the most useful output available) · with/without-4th-subject
  comparison · the retake rule (the new grade **replaces** the old).
- ⚠️ **Explicitly NOT recommended: per-university percentage conversion.** Essential in India
  (employers ask for a percentage, each university has its own formula). Unnecessary in BD — a

  the scale". Copying the Indian model would invent a problem.
- **The one real differentiator we lack:** `nucgpa.com`'s **pre-loaded syllabi per department** —
  it removes the data entry that makes every other CGPA calculator tedious. Also the only option
  with an ongoing maintenance cost → needs an owner decision.
- **Not competitors:** WES / ECE / Scholaro — credential *evaluation* for study abroad, a paid
  official service. Point at them rather than replace them.

# 🚨 CI failed on the first push — and it was a real defect in S14

**Pushed 7 commits; CI went red at "Verify internal links" with 26 broken targets:**
`/api/photocard/<id>.png` and `/api/idcard/<SHK-R-…>.png`, all **same-origin relative paths**.

## Why it passed locally every single time
`frontend/.env` sets `PUBLIC_CMS_ORIGIN`, so the card URLs were **absolute** and `verify:links`
ignores off-origin links. **CI leaves the variable unset on purpose** — its step comment says so,
because the interactive islands are meant to self-hide without it.

`ShareRow.astro` and `reporters/[slug].astro` read the **raw** `import.meta.env.PUBLIC_CMS_ORIGIN`
and fell back to `?? ''` → a same-origin `/api/…` path the static host does not serve.

⚠️ **`ShareRow`'s own comment claimed the opposite** — "an unset `PUBLIC_CMS_ORIGIN` hides the
button rather than emitting a link to a path the static host does not serve". The comment stated
the intent; the code did the reverse. **Same shape as the S14 not-found defect: a comment
asserting behaviour the code lacks.** That is now twice in one section — treat a comment that
describes a *negative* behaviour (hides, refuses, skips) as a claim to verify, not documentation.

## The fix
Both read through **`getPublicCmsOrigin()`** — the established helper. It returns the configured
origin, or the local `CMS_URL` during dev, or **`null`**; `null` means the section is not rendered.

## How it was found and proved
Reproduced locally first: copied `frontend/.env` aside (cross-device `mv` fails — use `cp` then
`rm`), supplied CI's env (`CMS_URL` + `PUBLIC_MEDIA_BASE_URL`), built → **the same 26 missing
links**. Applied the fix, rebuilt in the same env → cards render as absolute URLs, `verify:links`
passes. `.env` restored **byte-identical** (md5 compared).

Then pushed and watched the runner: **all 25 CI steps green**, including the two new
`verify:gpa` / `verify:cgpa` steps.

## Lesson
**A green local run is a hypothesis; the runner is the evidence.** The handoff has said this since
S0 and it was still worth re-learning. A harness that reads a developer's `.env` passes on every
machine that has one and fails only where it matters.
