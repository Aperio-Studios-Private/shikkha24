## ⚠️ The frontend is STATIC — a CMS edit does not change the site
The CMS is read **at build time only**. Editing `/admin` changes the database and nothing else; a rebuild is what publishes it. **When the owner says "I changed it in the CMS and nothing happened", check the build before the code.** Locally: `scripts/with-cms.sh bash -c "pnpm run build:frontend"` (a plain `build:frontend` is a **34-page thin build**; the real one is **876 pages on 2026-10-01** and grows with content, so assert "far more than 34", never one exact number). In production `DEPLOY_WEBHOOK_URL` is what triggers it — currently **unset**, and the CMS says so in its own admin description now.
- ⚠️ **Media URLs must go through `mediaUrl()`.** Payload stores a **relative** `/api/media/file/…` and the static host serves no `/api/`, so a raw `src={x.url}` is a silent 404 in the browser (green build, valid markup). `AdCreative.astro` shipped that bug until 2026-09-18. `verify:links` catches this class — but only once content referencing it exists.
- ⚠️ **`cmsFetch`'s response cache is disabled in dev** (`CACHE_ENABLED = !import.meta.env.DEV`). It is a build-time concurrency control; with no invalidation it froze CMS data for the life of an `astro dev` process.

## Top contracts (easy to break unknowingly)
- **`AD_POSITIONS` = contract.** No raw-HTML ad field, no `clickCount`. AdSense on `requestIdleCallback`, zero requests when unconfigured.
- **Two-profile CSP in `.htaccess` via `SetEnvIf Request_URI` + `Header ... env=`.** ⚠️ **`<LocationMatch>` is ILLEGAL in `.htaccess`** — it returns HTTP 500 sitewide. ⚠️ `<FilesMatch>` matches the **basename, not the path**. ⚠️ `Request_URI` **includes the query string** (patterns need `(\?.*)?$`). **A route is relaxed because it RENDERS AN AD SLOT** (`data-ad-slot`) — not because of its JSON-LD type or its listing-ness; `/latest` is a listing and is correctly strict. Article rule = 3 segments **minus** a middle `page` (`(?!page/)`), because `/latest/page/:n` is also 3 segments. Verified by `pnpm verify:apache` — a **real Apache** over the real `dist/`; never by reimplementing the matching, and never by asserting a proxy.
- **Self-hiding islands:** `getPublicCmsOrigin()` null → control not rendered (live-blog, poll, bookmark, reminder, social login).
- **⚠️ Custom endpoints MUST be mounted on a collection, with a relative path.** A root endpoint whose first segment equals a collection slug is shadowed by that collection's generated REST route — `/api/bookmarks/sync` would be read as "collection `bookmarks`, document id `sync`" and 404 forever. This is the `/api/comments/submit` lesson (`docs/security.md` §13.4). Collection endpoints are matched first.
- **⚠️ `readerIdFromRequest(req)` (in `lib/reader-session.ts`) is the ONLY place that decides who a reader request is.** It parses and range-checks the signed session id — the token carries a string, the columns are numeric. Never re-implement it; never cast.
- **⚠️ Bookmark sync's merge policy is a data-loss contract.** First sync **merges** (the local list is then *independent*, not stale — that is what carries pre-login bookmarks); every sync after takes the **server's** answer; a local change whose push failed **outranks** the server. The marker is `readers.bookmarksSyncedAt` — on the **reader**, never in local storage, because a per-device marker lets a device that lost its storage resurrect a deletion. A naive union re-adds a bookmark the reader deleted elsewhere. Asserted by `verify:endpoints` (HTTP) and `verify:bookmarks` (pure merge).
- **⚠️ `overrideAccess: true` bypasses field-level access** on public handlers — protection is the key-by-key whitelist.
- **Newsletter = resumable batch** (`sentThroughId`). Cron triggers disabled while token unset. Readers: no password, email optional. Account linking deliberately not implemented.
- **`vite.build.assetsInlineLimit: 0`** — Astro inlines small scripts; strict CSP blocks them. Assert 0 inline scripts.
- **Mid-article ads need ≥6 paragraphs.** Sponsored: excluded from masthead/ticker, kept in feed with «বিজ্ঞাপন». Feed excludes masthead story by **slug**.
- **⚠️ THREE CMS-host values — do not confuse.** `CMS_URL` = read at **build** time, all content is fetched from it. `PUBLIC_CMS_ORIGIN` = **browser-facing** origin for interactive islands (empty ⇒ self-hide). `PUBLIC_MEDIA_BASE_URL` = **browser-facing** origin for media; `mediaUrl()` prefixes the CMS's relative `/api/media/file/…` with it, and **unset it emits that path as-is so every article image 404s** (the static host serves no `/api/`). Setting only `PUBLIC_CMS_ORIGIN` gives a **green 32-page thin build** instead of 84. A green build ≠ a full build: always assert the **page count**, never the exit code.
- **IP forwarding:** `clientIp()` reads `x-forwarded-for` → `x-real-ip` → `unknown` (no `cf-connecting-ip` — Cloudflare removed).
- **⚠️ All date formatting MUST use `formatBnBd()` from `bangla-date.ts`.** Never call `toLocaleDateString('bn-BD')` without `timeZone: 'Asia/Dhaka'` — in UTC CI it shows the wrong day and the date-filter month key disagrees with the byline. Use `getDhakaYearMonth()` for `YYYY-MM` filter keys, never `toISOString().slice(0,7)`.
- **⚠️ `.astro` frontmatter is NOT typechecked.** `tsc` only sees `.ts/.tsx`; `@astrojs/check` (which would cover `.astro`) rejects TS 7, which is why Biome was adopted. So an identifier used in frontmatter without an import is **neither a type nor a lint error** — it is a `ReferenceError` at build time, thrown **only if that component actually renders**. The 2026-09-16 timezone fix shipped two such imports (`CommentSection`, `DeadlineStrip`) and the thin build hid both. Gate: **`pnpm verify:astro-imports`**. (Related: a thin build hides crashes, not just missing pages.)
- **⚠️ Publishing is guarded by `guardPublishStatus`, not by collection access.** `Articles.update` is `isEditorial` — it **must** include reporters so they can save drafts, so it cannot restrict publishing, and `_status` has no field-level access. The hook throws on the transition into `published` for non-editors (it throws rather than stripping, so a reporter is never told a stripped write succeeded).
- **⚠️ `isSelfOrAdmin` is for `users` only — never `authors`.** It compares the document id to the **user** id, which is right where the two are the same row and wrong for `authors`, whose link is `Users.authorProfile → authors`; the `where` matches nothing and the reporter gets a flat 403 on their own record. Use `isOwnAuthorProfileOrEditor`.
- **⚠️ The `verify-` namespace is reserved** for `verify:reporter` fixtures (author/category slugs, user emails). The harness purges it at startup and cleans up in a `finally`; a crashed run's leftovers otherwise generate **real pages** (`/reporters/verify-a-…` appeared in `dist/`).
- **⚠️ Institution fields live in `cms/src/lib/institution-fields.ts`, inside Payload `tabs`.** Tabs are **presentational** — `payload generate:types` output is byte-identical with and without them — but a flat `collection.fields.find` does **not** descend into them, so any harness reading field config must traverse `tabs` (`verify:access`'s `ownFields()` does). Adding a field means editing that module, not the collection.
- **⚠️ The institution directory is 724 imported rows and Wikidata carries NO discipline** (706 have none). The nav is the **ownership** axis (4 populated categories) plus a data-gated discipline filter; "Engineering = `discipline:engineering`" stays a 7-entry filter until an editor fills the field. Do not build a nav category that can be empty. ⚠️ **`discipline` is author-only — both automations were tested and are wrong** (a keyword rule files a *business* university as engineering; deriving from faculties files Dhaka as engineering because it has one). Spec §8.2. Do not re-derive a heuristic.
- **⚠️ Wikidata DOES carry faculties and departments** — `P527` on 64 of 940 items: 58 parts typed `faculty`, 41 with a Bengali label, holding 179 Bengali-labelled departments (Rajshahi 11 · Chittagong 10 · Dhaka 8). The import takes them, but they are **partial**, so the profile page prints an attribution note under that heading. **Before writing "no source carries X", query the source** — this repo asserted the opposite twice, in the spec and in a code comment, and both were wrong.
- **⚠️ Payload gives array sub-rows a fresh `id` on every read.** Comparing an array field against the stored value makes **every** row look modified and destroys idempotency reporting. Strip `id` before comparing (the import's `comparable()` does).
- **⚠️ `Articles.university` is the ONLY entry point** for the institution↔article link — the profile queries it, so publishing is the whole job. The demo seed must match institutions on **slug OR Bengali name**, because S19's import **adopts and re-slugs** a row whose name already exists (and re-slugs it because `seed:demo:purge` deletes `demo-` slugs).

## Secrets (audited 2026-10-01)
- **Everything is env-only, and a required secret THROWS rather than defaulting.** `requireEnv()` (`payload.config.ts`) and `requirePayloadSecret()` (`lib/signed-token.ts`). **Never add a `|| 'literal'` fallback** — two existed (reaction fingerprint, poll-voter hash) and both were real findings: a published key makes those anti-stuffing hashes forgeable.
- **⚠️ Harness fixtures must use a RANDOM password per run, never a literal.** `verify:reporter` used to create a **superAdmin** with a hardcoded password; a crash before the `finally` leaves a live admin account with a published credential.
- **⚠️ `.env` is git-ignored; only `.env.example` is tracked, placeholders only.** Git history is clean — no `.env` was ever committed.
- **⚠️ Scanning for leaks means scanning by VALUE, not by name.** Vite inlines env values into built JS, so grepping for `PAYLOAD_SECRET` proves nothing. Read the env files, classify each value, then search every built file for the sensitive ones. Done: 0 hits across 934 files.
- **Token gates fail closed:** unset `PUSH_SEND_TOKEN` / `NEWSLETTER_SEND_TOKEN` authorises **nobody** (both `timingSafeEqual`).

## Reader data (audited 2026-10-01)
- **⚠️ Readers have NO password** (`disableLocalStrategy`). Only `users` do, hashed with Payload's PBKDF2-HMAC-SHA256 (25,000 iterations, 32-byte salt) — a real KDF, **not** "SHA256 alone". **No config knob exists**; changing it means patching Payload.
- **⚠️ PII fields must stay field-level restricted.** `Comments.userEmail`, `CitizenSubmissions.reporterEmail`/`.reporterPhone` are `read: Boolean(req.user)` — defence in depth, so a loosened collection rule still cannot enumerate them anonymously.
- **⚠️ No raw IP is ever stored.** Reactions and poll votes keep a one-way HMAC of IP + UA only; rate limits are in-memory. This is also why those rows **cannot be deleted on request** — nothing identifies the person, which is the point.
- **⚠️ Account deletion anonymises comments rather than deleting them** (`endpoints/account.ts`). A published comment is public record; the byline becomes «একজন পাঠক», the email clears, the reader link drops. The UI says so up front.
- **⚠️ `forgetBookmarkSync()` must clear the sync MARKER, not just the list.** Leaving the marker makes a later account on the same browser look "already synced", and its first sync then DISCARDS the local list instead of merging it.
- **⚠️ Auditing a data flow means checking the RESPONSE SHAPE, not just access rules.** Every public endpoint returns `{ok:true}` or a deliberately narrow object; `/api/oauth/me` returns id/name/avatar/provider and never email or provider id. A correct access rule can still be undone by a response that echoes too much.

## Environment traps (top 7; rest in `sandbox-build-traps` skill)
0. **⚠️ `pnpm run` HANGS here — and this was once misread as a hung Payload schema push, which cost a session and six reverted files.** pnpm 11 runs a pre-run dependency check that shells out to `pnpm install`; the sandbox broker refuses it (`CODEBUDDY_BROKER_DENY EEXIST`) or **hangs indefinitely** (10 min observed). **Fix: run the tool directly** — `cms/node_modules/.bin/payload run <script>` — or use a `pnpm` shim that injects `--config.verify-deps-before-run=false`. `node_modules` is already complete; the check is never needed.
1. **`HTTP_PROXY` set → CMS fetches fail 502.** `NO_PROXY=localhost,127.0.0.1,::1`.
2. **Safe-delete shim aborts `astro build`** after pages written. `CODEBUDDY_SAFE_DELETE_ENABLED=0`.
3. **Parallel edits to same file silently lose writes.** Serialize; read back. ⚠️ It also drops an edit when the edits are sequential but interleaved with other tool calls — always read the value back, and after any bulk edit run a check that would catch a missing line (this is how the two missing `formatBnBd` imports were found, late).
4. **Drizzle stale-index trap:** the push re-emits `CREATE INDEX` for indexes that already exist → `index … already exists`. ⚠️ **It only bites a PRE-EXISTING database whose schema predates the change** — a **fresh** DB pushes cleanly *and* is idempotent (verified), so CI (fresh `ci.db`) is never at risk. Fix: `DROP INDEX IF EXISTS <name>`, retry, iterate (Hit 3× in S9). Adding a **collection** triggers it too (`payload_locked_documents_rels` rebuilds). To preserve data across a rename, `ALTER TABLE … RENAME COLUMN` **before** the push — `DROP COLUMN` takes the data.
5. **⚠️ Shell `grep` with `\|` alternation silently returns nothing here (zsh).** Cost two false "my edits did not land" conclusions. **Use the Grep tool**, never shell grep for alternation.
6. **⚠️ `verify:apache` cannot run on the full tree in this sandbox.** Its `cpSync` of the whole `dist/` (876 pages) exceeds the brokered filesystem's limit and dies **before any assertion** with `CODEBUDDY_BROKER_OUTCOME_UNKNOWN: read failed: Resource temporarily unavailable`. Not a code defect and not transient — **CI has no broker, so the full run is fine there.** Locally, temporarily move `dist/institutions` aside (keeping a few institution dirs so those routes stay covered), run it, restore.

## Deployment readiness (audited 2026-10-01)
- **⚠️ The CMS must carry security headers, not only the static frontend.** `.htaccess` already has HSTS, nosniff, X-Frame-Options DENY, CSP etc — but the Next.js API surface had **none**. Added via `headers()` in `next.config.ts` with an API-safe CSP (`default-src 'none'`).
- **⚠️ Auth endpoints need PER-IP rate limiting, not only per-account lockout.** Payload's `maxLoginAttempts: 5` is per-account; an attacker can try 5 passwords against every account. Implemented as specific Next.js route handlers (`/api/users/login/route.ts`, `/api/users/forgot-password/route.ts`) that take precedence over the catch-all `[...slug]`, check the limit, return 429 with `Retry-After`, and delegate to `REST_POST(config)`. **Next 16 deprecated middleware; Payload's `beforeLogin` runs AFTER the password check; auth operations have no hooks.** A specific route handler is the only intercept point.
- **Error responses are clean by construction:** no stack trace, SQL, file path or internal detail leaks. Verified by probing the real API.
- **CORS is an explicit allow-list**, not wildcard. Production: only `PUBLIC_SITE_URL`; localhost is gated on `NODE_ENV !== 'production'`.

## Security (audited 2026-10-01)
- **⚠️ `mediaFilePath` must validate path boundaries.** `path.resolve()` alone is not enough — it must be followed by `resolved.startsWith(base + path.sep)`. Payload sanitises filenames, but a second line of defence prevents arbitrary file read if that layer is bypassed (CVE, compromised admin, database tampering).
- **⚠️ Never define a second copy of `clientIp()`.** `lib/http.ts` has the canonical implementation; a local duplicate in `poll-vote.ts` risked divergence. Import the shared one.
- **⚠️ Password reset token is not explicitly cleared after use.** Payload sets `resetPasswordExpiration` to the current date, which effectively invalidates it. The token string remains in the DB — not exploitable today, but a latent risk if a backup is restored or the expiration check regresses. Fix: an `afterChange` hook that nulls the token when expiration is in the past.
- **⚠️ Stateless reader sessions cannot be revoked server-side.** Logout clears the cookie; a stolen copy remains valid for 30 days. This is the standard trade-off for stateless sessions, mitigated by `HttpOnly; Secure; SameSite=Lax`. Adding revocability would require a session-generation counter on the reader row.
- **The audit found NO exploitable vulnerabilities in:** IDOR (every endpoint derives identity from the session), SQL injection (zero raw SQL), XSS (all text escaped, `safeUrl` rejects `javascript:`/`data:`), mass assignment (no body spread anywhere), open redirect (OAuth `next` inside signed state).
