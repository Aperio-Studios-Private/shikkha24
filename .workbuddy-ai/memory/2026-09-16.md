# 2026-09-16

## Timezone defect fix — date formatting anchored to Asia/Dhaka

**Problem**: `toLocaleDateString('bn-BD')` without `timeZone` uses the runtime's
local TZ. In CI (UTC), a story published at 02:00 Dhaka on 1 Sep displays as
"31 August" and the date-filter month key (`2026-08`) disagrees with the
displayed date.

**Fix**: Added `formatBnBd()`, `getDhakaYearMonth()`, `getDhakaDate()` to
`frontend/src/lib/bangla-date.ts`. All use `Intl.DateTimeFormat` with
`timeZone: 'Asia/Dhaka'`. Replaced 20 call sites across 20 files:
- Components: ArticleCard, DeadlineStrip, AuthorCard, CorrectionNotice,
  CommentSection, Header
- Pages: [category]/[id]/[slug], page/[slug], privacy-policy, terms-of-use,
  circulars, quiz/[id], quiz/index, bookmarks, results/index, exams,
  deadlines, scholarships/index
- Lib: cms.ts (archive bucket keys + labels)

Article page's `publishedMonth` filter key now uses `getDhakaYearMonth()`
instead of `toISOString().slice(0,7)`.

**Counter-proof** (UTC simulation):
- Input: `2026-08-31T20:00:00Z` (= 02:00 Dhaka on 1 Sep)
- OLD: display="31 August", filter=2026-08 (wrong)
- NEW: display="1 September", filter=2026-09 (correct)

**Verification**: tsc pass, Biome lint pass (5 pre-existing warnings),
astro build pass (33-page thin build). Build-output verification: 2
pre-existing failures (no article pages in thin build — not caused by this fix).
