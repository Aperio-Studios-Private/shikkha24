## S0 verification COMPLETE — resolved with pnpm (follow-up to `aa1afe6`)

- **Request:** "continue".
- **Resolution:** the npm blocker was **not** a security bypass. `pnpm install` succeeds where npm fails — pnpm's directory-creation pattern is permitted by the filesystem broker. pnpm is also the better fit: Payload's own template targets it (`workspace:*` + `pnpm.onlyBuiltDependencies`), `astro@7.3.2` declares `pnpm >=7.1.0` in engines, and pnpm blocks post-install scripts by default (a supply-chain win for a stack with five native toolchains). Project is now pnpm-only; stale npm lockfiles deleted.
- **All gates measured:** lint/typecheck/build all exit 0 for both workspaces; **Astro incremental build ~1s**; **Next standalone 114 MB** (target 300–600 MB); **SQLite WAL 6/6 writers, 240/240 rows, integrity ok**; **Payload admin HTTP 200**; **standalone start path verified**; font budget 179.7 KB / 200 KB.
- **Four new findings, all fixed:** Turbopack `root` must be the monorepo root (not the app dir) in a pnpm monorepo; TypeScript 7 **removed `baseUrl`** (TS5102) which Payload's template still sets; the standalone entry is `.next/standalone/cms/server.js` (not `.../server.js`); Next does **not** copy `.next/static` into the standalone bundle.
- **Deferred:** Lighthouse CI / broken-link / JSON-LD gates need real page templates → S3+.
